# Контракт исследования → контент-машина

Зафиксировано 17.09.2026. Причина: код исследования перестраивался несколько
раз за неделю, и контент-машина не должна гадать, что уцелело. Здесь —
договор: имена полей, откуда каждое берётся и какой у него вид. **Имена полей
не переименовываются.** Если поле меняет форму или исчезает, мы пишем об этом
строкой в ту же минуту, а не документом задним числом.

Сторож: `tests/contract-fields.test.js` собирает пакет из полного набора данных
и падает, если хоть одно обязательное поле приехало пустым или пропало. То есть
сломать контракт молча теперь нельзя.

## Как получить пакет

`CAContract.buildAgentPackage(brief, lang, results, report)` из `lib/contract.js`.

Верхний уровень:

| Поле | Что внутри |
|---|---|
| `schema_version` | 3 |
| `generated_at` | ISO-время сборки |
| `research_language` | язык исследования, данные НЕ переводятся |
| `failed_modules` | модули, которые не отработали: `{module, niche, error, at}` |
| `project` | бриф целиком |
| `brand_assets` | `logo`, `colors[]`, `fonts[]`, `socials[]` — адреса нормализованы до `https://` |
| `owner_platforms` | решения человека: `already_running[]`, `taken_into_work[]`, `vc_articles[]` |
| `niches` | карта разведки ниш (M2) |
| `selected_niches` | какие ниши реально исследованы |
| `key_data` | проектный уровень: `AUDIENCE_SEGMENTS`, `RESEARCH_SOURCES` |
| `global_modules` | модули без ниши |
| `research_by_niche` | по каждой нише: `key_data` + `modules` |

## Поля, которых исследование НЕ выдаёт

Объявлены в пакете и всегда пусты: `PERSONA_ARCHETYPES`, `VISUAL_STRATEGY`,
`CONTENT_SYSTEM`, `CREATIVE_BRIEFS`, `LANDING_TZ`. Их делал модуль `CONTENT`
(блоки 18–22), которого в цепочке больше нет — сейчас M1…M9. Строит это
контент-машина у себя, из офферов, возражений и банка болей. Ключи оставлены,
чтобы чужой код не падал на отсутствии поля.

## Кто что читает (сверено с контент-машиной 17.09.2026)

Контент-машина читает: `CHANNEL_STRATEGY` (с «Решением» и «Почему нет»),
`owner_platforms`, `AUDIENCE_CHANNELS`, `ALTERNATIVES`, `COGNITIVE_TACTICS`,
`OFFERS_FINAL`, `MAIN_BET`, `OBJECTIONS`, `PAIN_BANK`, `HOOK_BANK`,
`AWARENESS_MIX`, `GUARDRAILS`.

`RESEARCH_SOURCES` она осознанно не читает: источники нужны человеку в отчёте,
генерации — нет, ссылки в текст берутся только из разрешённого списка.

**Решение человека сильнее вывода модели.** Если модуль поставил площадке
«не идём», а владелица взяла её в работу кнопкой (`owner_platforms.taken_into_work`),
побеждает человек — отказ снимается. Это правило действует на обеих сторонах
стыка, у контент-машины на него есть тест.

**ТЗ лендинга делает контент-машина** из `OFFERS_FINAL`, `MAIN_BET`,
`OBJECTIONS`, `PAIN_BANK`, `HOOK_BANK`. Исследование его не выдаёт — см.
раздел выше.

### Три поля про каналы — не путать

- `AUDIENCE_CHANNELS` (M5) — **где аудитория говорит**: форумы, чаты, отзывы.
  Оттуда взяты цитаты, туда можно приходить отвечать.
- `AUDIENCE_VOICES` (M4) — **кого аудитория читает**: блогеры, эксперты,
  сообщества, медиа. С ними работают гостевым выпуском, комментарием, рекламой.
- `CONTENT_CHANNELS` (M4) — **каналы конкурентов**. `CLIENT_CHANNELS` (M4) —
  каналы самого клиента.

## Правила, которые не меняются

- Имена полей неприкосновенны. Добавлять новые можно, переименовывать — нет.
- Данные на языке исследования, без перевода.
- Пустой массив значит «данных нет», а не «модуль не отработал»: для второго
  есть `failed_modules`.
- У каждой общей таблицы базы один пишущий. `audience_research` пишем мы,
  контент-машина читает.

## Что добавилось 17.09.2026

- `AUDIENCE_VOICES` (M4 · BLOCK 24E) — кого аудитория читает, кроме самих
  продавцов: блогеры, эксперты, сообщества, отраслевые медиа, подкасты. С ними
  работают иначе, чем с конкурентами: гостевой выпуск, комментарий, разбор их
  темы по-своему, реклама.

- `owner_platforms` — решения человека по площадкам: где уже публикуется, что
  взял в работу из «не идём», ссылки на свои статьи vc.ru.
- В `CHANNEL_STRATEGY` — колонки «Решение» и «Почему нет»: модуль разбирает
  ВСЕ площадки, а не только те, куда идём.
- `CLIENT_CHANNELS` снова наполняется: в строгом формате таблица BLOCK 24D не
  собиралась, и поле молча приезжало пустым.
- `AWARENESS_MIX` собирается из таблицы, а не только из CHART_DATA, которого
  строгий формат не выдаёт.
