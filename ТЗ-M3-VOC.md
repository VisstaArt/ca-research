## Зачем

Аудит от 19.07.2026 (`ФИДБЕК-2-M1-M7-2НИШИ.md`): «без настоящего сегментного VoC
модули M3–M6 остаются красиво оформленными гипотезами». M3 — фундамент. Пока он

**Цель:** на самом ценном измерении — реальные слова реальной ЦА — выйти из
паритета с бесплатным ChatGPT в явное преимущество.

## Ограничение

Без хрупких платформенных API (Reddit-подобная зависимость убила GummySearch
в ноябре 2025) и без дорогих데이터-вендоров. Только: поиск, загрузка страниц,
модели, эмбеддинги.

## Пять дефектов и пять механизмов

### Дефект 1. Общий поиск приводит на мусорные отзовики

**Механизм: реестр площадок по нише + поиск с ограничением по доменам.**

Вместо одного запроса «отзывы о X» — N запросов, ограниченных доменами из реестра.
Tavily поддерживает фильтрацию по доменам, новый сервис не нужен.

Реестр строится один раз на нишу (и переиспользуется):
- **отзывы на конкурентов** — лучший источник: жалоба на конкурента = боль + язык
  + подсказка по фиче одновременно
- профильные форумы и отраслевые сообщества
- комментарии под статьями (VC.ru, Хабр, отраслевые СМИ)
- Q&A-площадки (Яндекс.Кью, профильные)
- **комментарии YouTube** — официальный бесплатный API, не хрупкий
- маркетплейсы приложений — отзывы на конкурирующие продукты

Реестр — отдельная сущность в БД, наполняется поиском + вручную, накапливается
по нишам. Со временем это самостоятельный актив.

### Дефект 2. Цитаты фабрикуются или искажаются

**Механизм: программная верификация подстроки. Главное изменение.**

Для каждой цитаты:
1. Загрузить страницу по URL
2. Проверить программно, что **точная строка цитаты присутствует** в тексте страницы
3. Нет совпадения → цитата отбрасывается, без обсуждения с моделью

Это не промпт и не просьба к модели. Это проверка кода. Фабрикация становится
**структурно невозможной**, а не «нежелательной».

Побочный эффект: URL автоматически валиден, потому что страница загрузилась.

### Дефект 3. Цитаты не от квалифицированного сегмента

**Механизм: двухступенчатая фильтрация — эмбеддинги, потом судья.**

1. **Дешёвый проход эмбеддингами.** Считать близость цитаты к описанию сегмента и
   к формулировке исследуемой боли. Отсечь явно далёкое. Сотни цитат
   фильтруются за копейки
2. **Дорогой проход моделью-судьёй** по выжившим. Отдельный вызов, который видит
   только цитату + критерии сегмента — **не тот же вызов, что собирал**, иначе
   модель оправдывает собственный результат. Решение бинарное, с причиной отказа

Отказы логировать: по ним видно, где реестр площадок плохой.

### Дефект 4. Одна цитата в трёх персонах

**Механизм: дедупликация и бюджет цитат. Бухгалтерия, не ИИ.**

- Хеш цитаты + дедупликация по эмбеддингам (ловит перефразированные повторы)
- Жёсткое правило: одна цитата → одна персона
- Минимум N различных верифицированных цитат на персону, иначе персона
  помечается как гипотеза

### Дефект 5. Пустой VoC, но уверенные персоны

**Механизм: гейт перед M4–M6.**

Если верифицированных цитат по сегменту меньше порога:
- модуль возвращает «данных недостаточно» с числом найденного
- M4–M6 либо не запускаются по этому сегменту, либо весь блок маркируется
  «предварительно: VoC не собран»
- Confidence обязан ограничивать подачу вниз по цепочке, а не только стоять в ячейке

## Где нейронки реально усиливают

Не в генерации — в анализе:

### Кластеризация болей по эмбеддингам — главный качественный скачок

Сейчас: модель **называет** боли аудитории (то есть придумывает список).
Должно быть: боли **проявляются** из данных.

1. Эмбеддинги всех верифицированных цитат
2. Кластеризация
3. Каждый кластер = реальная боль, его размер = распространённость
4. Модель только **именует** кластер и выбирает из него репрезентативные цитаты

Разница принципиальная: список болей перестаёт быть выдумкой модели и становится
результатом измерения. **Именно этого GPT не делает**, и это невозможно
воспроизвести одним промптом.

Побочно: размер кластера даёт частотность боли — число, которого нет ни у кого.

### Прочее применение эмбеддингов
- Дедупликация near-duplicate цитат
- Привязка цитаты к сегменту по близости, а не по решению модели
- Сопоставление кластеров болей с офферами в M5/M6 — какая боль не закрыта

## Что это даёт против GPT

| | После переделки | GPT с deep research |
|---|---|---|
| Цитаты верифицированы в исходнике программно | да | нет |
| Боли получены кластеризацией, а не названы моделью | да | нет |
| Частотность боли (размер кластера) | да | нет |
| Привязка цитат к сегменту с логом отказов | да | нет |
| Гейт по достаточности данных | да | нет |

Это перестаёт быть процессным преимуществом и становится методологическим —
такое одним промптом не повторяется.

## Честно про объём

Не выходные. Реестр площадок → поиск по доменам → загрузка и парсинг →
верификация подстроки → эмбеддинги → кластеризация → судья → гейт.
Реалистично 2–4 недели сфокусированной работы.

Плюс известные потолки:
- часть сайтов блокирует загрузку — часть цитат будет теряться, это нормально
- закрытые Telegram-чаты и приватные сообщества недоступны — там лучший VoC,
  и он останется недостижимым
- загрузка страниц объёмом упирается в лимиты и стоит времени

## Порядок

1. Верификация подстроки — **делать первой**, она одна убирает фабрикацию
2. Реестр площадок + поиск по доменам
3. Дедупликация и бюджет цитат
4. Гейт по достаточности
5. Судья на эмбеддингах + модели
6. Кластеризация болей — последней, это надстройка над чистыми данными

Пункты 1–4 чинят продукт. Пункты 5–6 делают его лучше GPT.

## Не забыть
- Кодировка экспорта (mojibake) — час работы, но без неё продавать нельзя
- Конкуренты (M2) — тянуть с сайтов конкурентов, не из листиклов
