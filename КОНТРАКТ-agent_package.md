**Что изменилось в v2.** Исследование теперь идёт по нишам: каждая выбранная ниша получает
свой отдельный проход M2–M7 (свои конкуренты, свой VoC, свои персоны). В v1 модули лежали

Файл выгружается кнопкой в CA Research (`CA_<проект>_agent_package.json`). Это структурированный
результат исследования для потребителя (контент-машина LeadYup). Здесь описаны поля, чтобы на
стороне потребителя не парсить markdown заново.

## Базовые правила

- **Язык.** Все данные — на **языке исследования** (`research_language`), в подлинных
  формулировках аудитории, без перевода. Перевод туда-обратно убивает живые цитаты (VoC),
  поэтому его тут принципиально нет. Если нужен перевод для чтения — это делается на стороне
  потребителя как отдельный слой, а в работу (темники, скрипты) идёт оригинал.
- **Версионирование.** Завязывайтесь на `schema_version`. Значение может расти при добавлении
  модулей M8–M10; существующие поля в рамках версии 1 не переименовываются.
- **Пустые данные — это данные.** Если таблица пустая или значение «не замерено»/«гипотеза,
  не проверено» — так и передаётся. Не додумывайте: отсутствие цифры значит, что её не замеряли.

## Верхний уровень

| Поле | Тип | Что это |
|---|---|---|
| `schema_version` | number | Версия контракта (сейчас 3). |
| `generated_at` | ISO-строка | Когда выгружен пакет. |
| `research_language` | строка | Язык, на котором созданы и хранятся данные (напр. `Russian`). |
| `project` | объект | Бриф: название, гео, рынок, ниша, выбранные ниши/услуги и т.д. |
| `niches` | массив | Полная карта ниш со стоп-точки M1.2 (все кандидаты, не только выбранные — см. ниже). |
| `selected_niches` | массив строк | Какие из `niches[]` реально исследованы в этом прогоне — по этим именам смотреть `research_by_niche`. |
| `key_data` | объект | Проектный уровень, не по нише: `AUDIENCE_SEGMENTS` (M1.2 / BLOCK 04) — та же ссылка, что и в `key_data` каждой ниши ниже. |
| `global_modules` | объект | Модули без ниши (сейчас только `M1_2`): таблицы объектами + полный markdown. |
| `research_by_niche` | объект | По каждой исследованной нише — свои `key_data` и свои `modules` (M2–M7). См. ниже. |
| `executive_summary` | строка | Итоговый Decision Brief (markdown), если сгенерирован. |
| `price_layers` | объект | `{ available: [...], selected: [...] }` — ценовые слои, если использовались. |

## `niches[]` (со стоп-точки выбора ниши)

Каждый элемент:

| Поле | Тип | Пример |
|---|---|---|
| `name` | строка | «интернет-магазины» |
| `demand`, `competition`, `economics`, `fit` | number (1–5) | оценки |
| `score` | number | сумма |
| `verdict` | строка | `Go` / `Maybe` / `No-Go` |
| `why` | строка | одно предложение обоснования |
| `recommended` | bool | ровно у одной ниши `true` — рекомендация ИИ (человек мог выбрать другую) |

## `research_by_niche[<имя ниши>]`

Ключи объекта — точные имена ниш из `selected_niches` (те же строки, что и `name` в `niches[]`).
Каждая ниша:

| Поле | Тип | Что это |
|---|---|---|
| `key_data` | объект | Быстрые ссылки на самое нужное для ЭТОЙ ниши (см. таблицу ниже). |
| `modules` | объект | Модули M2–M7 этой ниши — та же форма, что описана в «`modules[<id>]`» ниже. |

### `research_by_niche[<ниша>].key_data`

Поля названы ТОЧНО как в контракте генерации (ТЗ-ИССЛЕДОВАНИЕ-ПОД-КОНТЕНТ.md разд.3) —
`import_research.py` на стороне `client-pipeline-template` подставляет их в
`ONBOARDING-INTAKE.md` один в один по имени поля, без переименования. Табличные поля — массив
объектов (строки соответствующей таблицы модуля, ключи = заголовки колонок на языке
исследования, могут слегка меняться между прогонами — читайте по имени колонки, не по индексу).

| Поле | Тип | Источник | Что внутри |
|---|---|---|---|
| `NICHE_DESCRIPTION` | строка | brief + имя ниши | одна фраза о теме/аудитории |
| `CHANNEL_FRAME` | строка | brief.extra | рамка/путь читателя, если задана в брифе (иначе пусто) |
| `AUDIENCE_PERSONAS` | массив | M4 / BLOCK 09 | персоны ЛПР: JTBD, боли, возражения, триггеры, каналы, цитаты |
| `AUDIENCE_SEGMENTS` | массив | M1.2 / BLOCK 04 (проектный уровень, продублирован сюда) | сегменты ЦА, платёжеспособность, квалификация |
| `VOICE_OF_CUSTOMER` | массив | M3 / BLOCK 07 | боли + дословные цитаты с URL, частотность, сегмент |
| `GUARDRAILS` | массив строк | M4 / BLOCK 12B (chartData.guardrails) | жёсткие правила для генерации, синтезированы из страхов BLOCK 12 |
| `TOPIC_FOCUS` | строка | brief.result | с чем должна быть связана практическая польза темы |
| `PAIN_BANK` | массив | M3 / BLOCK 07 + синтетический `pain_id` | те же строки, что VOICE_OF_CUSTOMER, с добавленным стабильным id для дедупа на стороне контент-машины |

| `OBJECTIONS` | массив | M4 / BLOCK 12 + синтетический `objection_id` | страхи/сомнения + артефакт для снятия — готовые темы наравне с PAIN_BANK |

## `modules[<id>]` (внутри `global_modules` или `research_by_niche[<ниша>].modules`)

В `global_modules` — ключ `M1_2`. В `research_by_niche[<ниша>].modules` — ключи `M2`…`M7`
(и позже `M8`–`M10`, если станут по-нишевыми). Форма записи одна и та же везде:

| Поле | Тип | Что это |
|---|---|---|
| `title` | строка | Название модуля на языке специалиста. |
| `generated_at` | ISO/`null` | Когда сгенерирован модуль. |
| `tables` | объект | `{ "<заголовок блока>": [ {строки}… ] }` — все таблицы модуля. |
| `markdown` | строка | Полный текст модуля без обрезки — на случай, если таблиц недостаточно. |

Ключи в `tables` — это заголовки блоков как в отчёте (например `BLOCK 07 — Voice of Customer…`,
`BLOCK 04_2 — Niche Prioritization Matrix`, `SEO-02 — Semantic Core`). При совпадении заголовков
второй получает суффикс ` (N)`.

## Что важно помнить потребителю

- **Проверяемость.** У цитат VoC и у конкурентов есть URL — их можно и нужно открывать.
  Ссылки `[n]` в тексте M1.2/M7 расшифровываются в блоке источников того же модуля.
- **Числа с оговоркой.** Частотности SEO, прогнозы трафика, «рост до X%» помечаются как
  гипотеза/не замерено. Не переносите их в рекламные тексты как факт.
- **Персоны и цитаты связаны.** URL у персоны (M4) должен встречаться в таблице VoC (M3) —
  это признак того, что персона построена на реальных данных, а не выдумана.
