## 1. Зачем и когда

Владелица: **боевой прогон делаем только после того, как все этапы оформлены.**
Иначе платные прогоны уйдут на то, что мы потом переделаем.

Оформление готово: 36 блоков в библиотеке. Осталось перенести его в сам отчёт.
Сейчас отчёт — плоские markdown-таблицы; библиотека — отдельная страница.
Пока они не сойдутся, ни один из них не является продуктом.

---

## 2. Главное решение: откуда берётся вёрстка

**Не из markdown.** Сейчас модель возвращает таблицы текстом, и любой формат
поверх них — это разбор текста регулярками. Он ломается от лишнего пробела,
от перевода строки внутри ячейки, от смены заголовка блока.

Правильный вход — **`agent_package.json`**, он для этого и заведён. Там каждый
блок уже лежит структурой: `modules[].tables[]` с массивами строк.

Порядок такой:

1. Блок отчёта → его данные берутся из `agent_package`, не из текста.
2. Данные → компонент оформления (один на каждый тип из библиотеки).
3. Markdown остаётся как **запасной вывод** для выгрузки и для случая,
   когда данных на блок не хватило.

Если для блока нет структурных данных — показывать markdown как сейчас, а не
пустой красивый контейнер. Отчёт обязан открываться при любой неполноте.

## 4. Правила оформления — соблюдать при любом новом блоке

Выведены владелицей за 10.09, каждое стоит денег в переделках:

1. **Полоса 14px, между строками 13px, под каждой полосой светлая дорожка во
   всю ширину, торцы прямые.** Эталон — блок «Приоритет ниш». Дорожка не
   украшение: без неё короткая полоса висит в пустоте и не с чем сравнить.
2. **Числа снаружи полосы, чернилами.** Внутри цветной плашки — нигде.
3. **Фирменную бирюзу не притемнять ради контраста** — получается чужой
   зелёный. Цвет живёт заливкой; буквами он не ставится, потому что на
   слоновой кости даёт 2.17 при норме 4.5.
4. **Подписи колонок — один раз в шапке**, не в каждой строке.
5. **Иконка цветная, когда она легенда; нейтральная, когда она картинка.**
   Значок рядом с заголовком таблицы не ставится вовсе.
6. **Панель с данными — сплошная, на `--raise`.** Стекло и перламутр — материал
   объектов (плитки, обложки), под данными поверхность ровная.
7. **Поверх фона-фотографии — только основные чернила.** Вторичные на тёмных
   участках дают 3.35.
8. **Палитра ровно четыре цвета:** `#06BDBD` бирюза, `#4DD1F7` голубой,
   `#4D66F7` фиолетовый, `#6E6C66` графит. Производных не изобретать.
9. **Одна величина — одна шкала светлоты, а не разные тона.** Разные тона
   читаются как разные ВЕЩИ.

## 5. Тёмная тема

Отложена владелицей осознанно. В библиотеке и оболочке для неё есть
минимальный набор токенов, но **фон-фотография в тёмной теме не работает** —
там нужен свой фон и пересчёт всех цветов. Не пытаться получить её
инверсией: это отдельная работа, а не переключатель.

## 6. Критерий приёмки

> открыть отчёт по одной нише: каждый блок из таблицы раздела 3 отрисован своим
> форматом, ни один не показывает markdown-таблицу; при этом если у блока
> нет структурных данных, он показывает markdown и отчёт не ломается

и отдельно:

> прогнать по разделу 4 глазами: найти на странице хоть одну полосу не 14px,
> хоть одно число внутри цветной плашки, хоть одну бирюзовую надпись. Не должно
> найтись ни одной
