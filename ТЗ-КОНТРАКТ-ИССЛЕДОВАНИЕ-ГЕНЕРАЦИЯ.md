# ТЗ: Исследование как задание для генератора
**Дата:** 22 августа 2026 · **Приоритет:** выше, чем углубление исследования

## Принцип

Исследование само по себе не продаётся — продаётся контент, который из него
получается. Значит улучшать его надо **не в глубину, а в форму**: на выходе
должно быть машиночитаемое задание для генераторов, а не отчёт для чтения.

Контракт не надо изобретать — он уже в коде `client-pipeline-template/prompts/*.md`.

## Что генераторы потребляют сегодня

| Поле | Кто использует | Даёт ли исследование |
|---|---|---|
| `NICHE_DESCRIPTION` | почти все промпты | да |
| `AUDIENCE_PERSONAS` | plan-pains, select-criteria | да (M4) |
| `AUDIENCE_SEGMENTS` | write-article | да (M1/M4) |
| `VOICE_OF_CUSTOMER` | **только select-criteria** | да (M3) |
| `GUARDRAILS` | plan-pains, select-criteria, write-carousel, write-style | частично |
| `TOPIC_FOCUS` | select-criteria | да |
| `PAIN_BANK` | plan-pains | да (M3/M4) |
| `SEO_KEYWORDS` | write-article | да (M7) |
| `CHANNEL_FRAME` | select-criteria | да |

Поля бренда (`BRAND_*`, `AUTHOR_*`, `PROMO_*`, `VOICE_REFERENCE`,
`VOICE_EXAMPLES`, `PUBLISH_PLATFORM`) заполняются вручную — исследование их
не касается.

## Три дырки, которые стоят дороже любой глубины

### 1. VoC не доходит до написания текста

`VOICE_OF_CUSTOMER` используется **только в `select-criteria.md`** — то есть
язык аудитории влияет на выбор темы, но не на то, как написан текст.
`write-style.md`, `write-carousel.md` и `write-article.md` его не получают.

Это главный промах контракта. Дословные формулировки аудитории — самое
ценное, что даёт исследование, и они не попадают туда, где пишется текст.

**Что сделать:** пробросить `VOICE_OF_CUSTOMER` во все три промпта написания.
Правка на час, эффект на качество текста прямой.

### 2. Уровни осознанности собираются, но никем не потребляются

M4 даёт распределение сегментов по L1–L5 (Шварц) в процентах. **Ни один промпт
генерации это поле не принимает.** Готовый актив простаивает.

Между тем это прямой рычаг качества: если 60% сегмента на L1 (не осознаёт
проблему), большая часть контента должна быть проблемно-осознающей, а не
продуктовой. Сейчас распределение форматов и углов ни на чём не основано.

**Что сделать:** новое поле `AWARENESS_MIX` → в `plan-pains.md` и
`select-criteria.md`. Контент-план строится по распределению, а не наугад.

### 3. Возражения не доходят до генерации

M4 собирает возражения, но поля для них в контракте нет. При этом **каждое
возражение — готовая тема поста**, а снятие возражения — самый конверсионный
формат.

**Что сделать:** новое поле `OBJECTIONS` → в `plan-pains.md` как отдельный
источник тем наравне с `PAIN_BANK`.

---

## Четвёртое: банк хуков

Сейчас хук придумывается моделью при написании. Но самый сильный хук в коротком
формате — **дословная фраза из VoC**: аудитория узнаёт свои слова.

**Что сделать:** новое поле `HOOK_BANK` — верифицированные цитаты, отобранные
по пригодности как первая строка (короткие, эмоциональные, от первого лица).
Потребители: `write-carousel.md`, будущие сценарии роликов.

Это и есть причина, по которой гигиена M3 всё-таки нужна: **не ради
достоверности отчёта, а потому что мусорная цитата даёт мусорный хук.**

---

## Итог: что дорабатывать в исследовании

**Делать:**
1. Пробросить `VOICE_OF_CUSTOMER` в промпты написания — час работы
2. Добавить `AWARENESS_MIX`, `OBJECTIONS`, `HOOK_BANK` в выход исследования
3. Гигиена M3 — пункты 1–4 из `ТЗ-M3-VOC.md` (верификация цитат, реестр
   площадок, дедупликация, гейт). Обоснование теперь другое: чистые цитаты
   нужны как сырьё для хуков и голоса, а не как украшение отчёта
4. Кодировка экспорта (mojibake)
5. `agent_package.json` привести в точное соответствие контракту — чтобы
   исследование заполняло поля анкеты автоматически, без ручного переноса

**Не делать:**
- Новые аналитические модули
- Углубление психологии, расширение разбора конкурентов
- Кластеризацию болей и модель-судью (пп. 5–6 `ТЗ-M3-VOC.md`)

Всё из второго списка делает отчёт толще, а контент — нет.

## Критерий приёмки

Не «отчёт стал глубже», а: **исследование прогнали → анкета онбординга
заполнилась автоматически → генератор выдал контент → контент опубликован →
пришёл клиент.**

Пока эта цепочка не замкнута хотя бы один раз, неизвестно, работает ли продукт.
